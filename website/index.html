पाणिनीयकारकतन्त्रम् • Pāṇinian Kāraka to Relational Mapping

In Pāṇini’s Aṣṭādhyāyī (1.4.23 to 1.4.55), participants in an action bear semantic roles (Kārakas) expressed via nominal case endings (Vibhaktis) around a central passive imperative verb (Karmaṇi Loṭ).

Static Grammatical Type Checking & Compiler Pipeline

1. Three Gender Concordance (लिङ्गसमन्वयः)

Every column in schema.सं declares its grammatical gender: Masculine (पुंलिङ्गम्), Feminine (स्त्रीलिङ्गम्), or Neuter (नपुंसकलिङ्गम्). Comparison pronouns (इत्यनेन vs. इत्यनया, इत्यस्मात् vs. इत्यस्याः) and predicate adjectives (समः/समा/समम्, अधिकः/अधिका/अधिकम्, रिक्तः/रिक्ता/रिक्तम्) are statically verified against the subject column’s gender.

2. Subject and Verb Number Agreement (वचनसमन्वयः)

Because SSQL queries are passive imperative sentences (Karmaṇi Prayoga), the terminal verb must agree in grammatical number with the count of projected columns: आह्रियताम् (1 column, एकवचनम्), आह्रियेताम् (2 columns, द्विवचनम्), or आह्रियन्ताम् (3+ columns, बहुवचनम्); सर्वम्, the collective shorthand for all table columns, is neuter singular and takes आह्रियताम्. Changing a projection between 1, 2, and 3+ columns without updating the verb is caught at compile time!

3. Pure User Defined Functions (शुद्धम् कार्यम्)

Declare a pure function’s parameters with the passive verb (दीयते/दीयेते/दीयन्ते, “is given”), and invoke them via Genitive (मूल्यस्य द्विगुणितम्) or प्रदाय (“having supplied”). The compiler expands them safely across both SQLite and PostgreSQL.

4. Bidirectional SQL ⇄ SSQL & Tooling

Migrate existing SQL codebases effortlessly with --from-sql, enforce canonical indentation with --fmt, verify Pāṇinian padapāṭha purity with --lint, and enjoy full IDE support with ssql-lsp and the VS Code Extension.
